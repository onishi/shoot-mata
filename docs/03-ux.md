# 03 UX と画面構成

## 画面の優先順位
1. 危険な敵弾と自機の位置。
2. 射撃モードとバースト可能状態。
3. 残機とスコア。
4. 背景と装飾。

プレイ領域の上端にHUD帯を置き、敵弾が帯の文字と重なる場合は帯に暗い背景を敷く。タイトルは「開始」ボタンと操作説明を同一画面に表示。結果画面は「再挑戦」を最も大きく示す。

## PC
- 960×540を基準に画面比を維持して中央へ配置。余り領域は暗色で埋める。
- キーボードを主入力とする。Space長押し射撃、Shift／X切替、Zバースト、P／Escapeポーズ。
- フォーカス中は自機の輪郭とHUDが黄色に変化し、ワイド中は水色。
- キー押下がブラウザスクロールを起こさないようにする。

## スマートフォン
- 縦持ちではゲーム画面を上部に16:9で配置し、下部に操作領域を置く。横持ちでは左右端に操作領域を重ね、敵弾と被らない配置を優先する。
- 左手の仮想スティック、右手の射撃・切替・バースト。射撃は押し続け、切替とバーストはタップ。
- 操作ボタンは少なくとも44 CSS px、ボタン間に8px以上の間隔を設ける。
- 端末差が大きいため、後続フェーズの実機テストで位置を調整する。

## 操作フローとフィードバック
タイトル → 開始 → プレイ → ポーズまたは結果 → 再開／再挑戦／タイトル。タブが非表示になったら自動でポーズ。復帰は明示操作とする。音は初期状態でOFFでも遊びの情報が失われない。ONはユーザー操作後に有効化する。

初回は操作一覧をタイトルに表示する。ゲーム中はフォーカス切替時に短いラベル、バースト可能時にゲージの明滅を出す。被弾直後は残機変化と無敵点滅を同期させる。色覚や小画面のため、モード名・残機数・ゲージ数値も併記する。
