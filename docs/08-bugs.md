## QA-001 結果確定後の回収
- 再現手順：残機を1、スコアを200にし、自機の座標に敵弾と回収物を同時に置いて1フレーム進める。
- 期待動作：ゲームオーバーでスコア200、エネルギー0のまま確定する。
- 実際の動作：ゲームオーバー後も回収処理が続き、スコア250・エネルギー2になる。
- 原因と修正：敵弾衝突で結果へ遷移したあとも回収物を処理していた。敵弾処理直後に結果状態なら更新を終了する。
- 再確認：失敗する回帰テストを追加して現象を確認後、修正後に17件の全テストで確認した。

## QA-002 ステージ番号と版の表示
- 再現手順：α版を開き、ページタイトル・ヘッダー・画面下の注記を見る。
- 期待動作：プレイするステージ01と現行の版を示す。
- 実際の動作：タイトルとヘッダーは「STAGE 02」、注記は「フェーズ07-02」と表示される。
- 原因と修正：前スライスから引き継いだ静的文言を更新していなかった。タイトル・ヘッダー・注記を現行の内容に修正する。
- 再確認：Chromeでページを再読み込みし、タイトルとヘッダーの「STAGE 01」、現行版の注記を画面で確認した。

## QA-003 高DPIのCanvas解像度
- 再現手順：DPR 2のChromeでPC幅のゲーム画面を開き、Canvasの表示寸法と `width`・`height` 属性を比べる。
- 期待動作：表示寸法1052×590 CSS pxなら、約2104×1180実ピクセルを確保する。サイズ変更後も追従する。
- 実際の動作：08-01ではDPR 2でも960×540実ピクセルのまま拡大していた。
- 原因と修正：Canvasの内部サイズを固定していた。08-02では表示寸法×DPRに合わせて実ピクセル数とCanvas変換を更新する。
- 再確認：DPR 2のPC幅で2104×1180、DPR 1の390×844縦画面で362×202、844×390横画面で565×316、320×568縦画面で292×163をChromeで確認。PCでクリアし、再挑戦中に横画面から小型縦画面へ変更した後もクリアできた。

## QA-004 狭い縦画面のセーフエリア
- 再現手順：Chromeの320×568で開発用の上24px・左右36px・下20pxの擬似セーフエリアを適用し、タイトル画面のFIREボタンを見る。
- 期待動作：FIREを含む操作部が画面端から余白を取り、見切れず操作できる。
- 実際の動作：固定幅のスティックとボタン群の合計が利用可能幅を超え、FIREの右側が画面外に出る。
- 重大度と原因：中。画面幅からセーフエリアを差し引いた操作可能幅をレイアウトへ反映していなかった。
- 修正：縦画面のスティックとボタン群を利用可能幅に応じて縮め、最低ボタン幅を保つ。横画面も操作部の左右と下側にセーフエリア余白を設ける。
- 再確認：擬似セーフエリアの320×568でFIRE右端284px、スティック左端36px。START・SWITCH・FIREを操作できた。844×390でも操作部が左右36px以上、下20px以上の余白内に収まった。物理端末では未確認。

## QA-005 音声開始中の切替重複
- 再現手順：遅延する `AudioContext.resume()` を用い、SOUNDをONにする処理が完了する前に再度切り替える。
- 期待動作：開始処理中の重複操作は受け付けず、処理完了後に表示と音声状態が一致する。
- 実際の動作：修正前は `resume()` が2回呼ばれ、2回目もONとして進む。ユーザーのOFF操作が反映されない。
- 重大度と原因：中。非同期の開始処理中にも旧状態のOFFを参照していた。
- 修正：音声切替に処理中フラグを設け、ボタンを一時的に無効化して `aria-busy` を付ける。開始失敗後はOFFへ戻して再操作を許す。
- 再確認：修正前に失敗するテストを追加。修正後は `resume()` 1回、保留中の重複操作はOFFのまま、完了後のOFF切替と開始失敗後の再試行に成功した。ChromeでOFF→ON→OFFの表示と `aria-pressed` を確認した。聴感は未評価。
