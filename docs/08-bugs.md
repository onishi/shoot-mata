## QA-001 結果確定後の回収
- 再現手順：残機を1、スコアを200にし、自機の座標に敵弾と回収物を同時に置いて1フレーム進める。
- 期待動作：ゲームオーバーでスコア200、エネルギー0のまま確定する。
- 実際の動作：ゲームオーバー後も回収処理が続き、スコア250・エネルギー2になる。
- 原因と修正：敵弾衝突で結果へ遷移したあとも回収物を処理していた。敵弾処理直後に結果状態なら更新を終了する。
- 再確認：失敗する回帰テストを追加して現象を確認後、修正後に17件の全テストで確認した。

## QA-002 ステージ番号と版の表示
- 再現手順：α版を開き、ページタイトル・ヘッダー・画面下の注記を見る。
- 期待動作：プレイするステージ01と現行の版を示す。
- 実際の動作：タイトルとヘッダーは「STAGE 02」、注記は「フェーズ07-02」と表示される。
- 原因と修正：前スライスから引き継いだ静的文言を更新していなかった。タイトル・ヘッダー・注記を現行の内容に修正する。
- 再確認：Chromeでページを再読み込みし、タイトルとヘッダーの「STAGE 01」、現行版の注記を画面で確認した。

## QA-003 高DPIのCanvas解像度
- 再現手順：DPR 2のChromeでPC幅のゲーム画面を開き、Canvasの表示寸法と `width`・`height` 属性を比べる。
- 期待動作：表示寸法1052×590 CSS pxなら、約2104×1180実ピクセルを確保する。サイズ変更後も追従する。
- 実際の動作：08-01ではDPR 2でも960×540実ピクセルのまま拡大していた。
- 原因と修正：Canvasの内部サイズを固定していた。08-02では表示寸法×DPRに合わせて実ピクセル数とCanvas変換を更新する。
- 再確認：DPR 2のPC幅で2104×1180、DPR 1の390×844縦画面で362×202、844×390横画面で565×316、320×568縦画面で292×163をChromeで確認。PCでクリアし、再挑戦中に横画面から小型縦画面へ変更した後もクリアできた。

## QA-004 狭い縦画面のセーフエリア
- 再現手順：Chromeの320×568で開発用の上24px・左右36px・下20pxの擬似セーフエリアを適用し、タイトル画面のFIREボタンを見る。
- 期待動作：FIREを含む操作部が画面端から余白を取り、見切れず操作できる。
- 実際の動作：固定幅のスティックとボタン群の合計が利用可能幅を超え、FIREの右側が画面外に出る。
- 重大度と原因：中。画面幅からセーフエリアを差し引いた操作可能幅をレイアウトへ反映していなかった。
- 修正：縦画面のスティックとボタン群を利用可能幅に応じて縮め、最低ボタン幅を保つ。横画面も操作部の左右と下側にセーフエリア余白を設ける。
- 再確認：擬似セーフエリアの320×568でFIRE右端284px、スティック左端36px。START・SWITCH・FIREを操作できた。844×390でも操作部が左右36px以上、下20px以上の余白内に収まった。物理端末では未確認。

## QA-005 音声開始中の切替重複
- 再現手順：遅延する `AudioContext.resume()` を用い、SOUNDをONにする処理が完了する前に再度切り替える。
- 期待動作：開始処理中の重複操作は受け付けず、処理完了後に表示と音声状態が一致する。
- 実際の動作：修正前は `resume()` が2回呼ばれ、2回目もONとして進む。ユーザーのOFF操作が反映されない。
- 重大度と原因：中。非同期の開始処理中にも旧状態のOFFを参照していた。
- 修正：音声切替に処理中フラグを設け、ボタンを一時的に無効化して `aria-busy` を付ける。開始失敗後はOFFへ戻して再操作を許す。
- 再確認：修正前に失敗するテストを追加。修正後は `resume()` 1回、保留中の重複操作はOFFのまま、完了後のOFF切替と開始失敗後の再試行に成功した。ChromeでOFF→ON→OFFの表示と `aria-pressed` を確認した。聴感は未評価。

## QA-006 ボタンのSpace操作
- 再現手順：08-08をChromeで開き、STARTボタンにキーボードでフォーカスしてSpaceを押す。
- 期待動作：STARTが起動してプレイ画面へ進む。他のボタンも同様にキーボード操作できる。
- 実際の動作：タイトル画面のまま。Spaceキーのグローバルな射撃処理が既定のボタン操作を抑止していた。
- 重大度と原因：中。キーボードのみで主要な画面遷移を操作できない。
- 修正：Spaceの対象がボタンの場合はゲームのキー入力として処理せず、ブラウザのボタン操作を通す。
- 再確認：08-09のChromeでSTART・RESUME・RETRYをSpace、TITLEをEnterで起動。SOUNDもSpaceでON/OFFが切り替わり、コンソールエラーは0件。ボタン以外の射撃入力経路は変更していない。

## QA-007 タッチ操作ボタンのキーボード操作
- 再現手順：08-09のSWITCH・BURST・FIREボタンにキーボードでフォーカスし、SpaceまたはEnterを押す。
- 期待動作：SWITCH・BURSTは一度ずつ起動し、FIREは押下中だけ射撃を維持する。ポインターとの同時押下後も入力が残らない。
- 実際の動作：各ボタンはポインターイベントのみを処理し、キー操作では起動しない。
- 重大度と原因：低。キーボードにはX・Z・Spaceの代替キーがあるが、画面上のボタンをフォーカスして操作できない。
- 修正：SWITCH・BURSTにSpace/Enterのキー処理を追加。FIREはキーとポインターを個別に保持し、フォーカス喪失や中断時に解除する。
- 再確認：修正前に失敗した2件の回帰テストが成功。Chromeの縦画面でSWITCHのSpace操作によるWIDE→FOCUSを確認。BURST・FIREの画面上の発動・射撃は未確認。

## QA-008 キャプチャ喪失後の保持入力
- 再現手順：スティックとFIREをポインターで押し、`pointerup`・`pointercancel` より先に各要素の `lostpointercapture` が届く条件を模擬する。
- 期待動作：該当ポインターの移動・射撃入力と押下表示を解除する。同時に押しているキーボードFIREは維持する。
- 実際の動作：修正前はキャプチャ喪失イベントを処理せず、スティックの移動とポインターFIREが残った。回帰テストはイベントのハンドラーが存在せず失敗した。
- 重大度と原因：中。押下終了イベントを受け取れないと、次の中断まで意図しない移動・射撃が続く可能性がある。
- 修正：`lostpointercapture` をポインター終了と同じ解除処理に通す。IDが異なるイベントは無視する。
- 再確認：08-11の回帰テストは修正後に成功。Safariで開始・敗北・再挑戦を確認した。実ブラウザでキャプチャ喪失を起こす操作と、押下中のタブ離脱は未実施。

## QA-009 バースト準備完了の表示
- 再現手順：エネルギーを5までため、Canvasのゲージと小画面のBURST表示を見る。
- 期待動作：`docs/03-ux.md` に沿い、満タン時にゲージの明滅と準備完了の文言で発動可能状態が分かる。
- 実際の動作：08-11ではゲージが緑色になるだけで、明滅と「READY」の文言はなかった。
- 重大度と原因：低。操作は可能だが、発動できる瞬間を見落としやすい。
- 修正：Canvasに「BURST READY」と交互に明るくなるゲージ、小画面HUDに「READY · 5 / 5」、BURSTボタンに強調表示を追加。動きを抑える設定ではCanvasの明滅とボタンのアニメーションを止め、静的な強調を維持する。
- 再確認：開発用 `?qa=burst-ready` でChromeのPC・390×844に準備完了を表示。ZまたはBURSTボタンで発動後は「BURST!」「ACTIVE」、終了後は「0 / 5」に戻り、準備完了表示が消えた。通常の回収による満タン到達と物理端末での視認性は未確認。

## QA-010 武器切替直後のモード名
- 再現手順：08-12でプレイを始め、XでWIDEとFOCUSを切り替えて自機付近の演出を見る。
- 期待動作：`docs/02-game-design.md` と `docs/03-ux.md` に沿い、切替直後に現在の武器名を短く表示する。
- 実際の動作：切替リングだけが表示され、自機付近にモード名は出ない。HUDのモード表示は更新される。
- 重大度と原因：低。切替は機能するが、切替直後の手元の視覚的な応答が設計を満たさない。
- 修正：切替イベントに新しいモードを含め、リングと同じ位置にWIDE／FOCUSを0.75秒のフェードで表示。連続切替では古い表示を置き換える。
- 再確認：08-13のSafariでXを押し、FOCUSとWIDEの表示をスクリーンショットで確認。連続切替で古い表示が残らないことと、時間経過で消えることは回帰テストで確認。物理端末の視認性は未確認。
