# 08 アルファ・ベータテスト計画と実施記録

## 対象と判定
対象は `phase-08-01/` から始まる独立したMVP版。現在の最新版は `phase-08-02/`。αでは主要フローと状態の整合、βでは操作性・視認性・負荷・端末差を調べる。合格は「実施した試験で主要フローが成立し、重大な既知不具合が残らない」。試験できない条件は合格扱いにしない。

| ゲームオーバー・クリア・結果確定 | 自動テスト、ブラウザ操作 | 結果とスコアが確定 | 合格。最後の残機と同時回収を回帰テストで確認。無操作の敗北、8倍速自動プレイのクリアをChromeで確認 |

## 不具合管理
`docs/08-bugs.md` に再現手順、期待動作、実際の動作、重大度、修正と再確認結果を残す。重大度は高（主要フローを妨げる）、中（結果や操作に影響）、低（限定条件の表示・演出）とする。

## 2026-10-10 αテスト実施記録
- 対象：`phase-08-01/`、Node.js 24、Chromeのローカル開発サーバー。`npm run typecheck`、17件の`npm test`、`npm run build`が成功した。GitHub Actionsのrun `38058622281` は全ジョブ成功。
- 回帰：QA-001のテストは修正前にスコア250となり失敗、修正後にスコア200・エネルギー0で合格。QA-002のタイトルと見出しはChromeで「STAGE 01」と再確認した。
- Chrome操作：START→ポーズ→再開、ポーズ→再挑戦とタイトル、ゲームオーバー→再挑戦、8倍速自動プレイの166秒クリア→タイトルを確認。縦画面ではSWITCHでFOCUSへ変わり、ポーズ画面のボタンが見切れないことを確認。開発コンソールのエラーは0件。
- 未実施：タブを本当に非表示にする操作は今回のブラウザ環境で再現できなかった。別タブを作っても元ページの `document.hidden` はfalseのままだったため、タブ離脱の合格とは扱わない。実機マルチタッチ、ブラウザ差、高DPI、測定を伴う性能、聴感、有人の約3分プレイも未実施。
- 判定：確認した主要フローに破綻はなく、既知の高重大度不具合は0件。`phase-08-01` のタブ離脱条件は未達であり、フェーズ08は継続する。

## 2026-10-10 βテスト実施記録
- 対象：独立した `phase-08-02/`。技術設計の高DPI条件に合わせ、Canvasの論理座標960×540を維持して表示寸法×DPRの実ピクセル数を確保した。画面サイズ変更時も更新する。
- QA-003の再確認：ChromeのDPR 2・PC幅ではCSS 1052×590 pxに対して実ピクセル2104×1180。DPR 1・390×844縦画面では362×202、844×390横画面では565×316、320×568縦画面では292×163へ追従した。PC・縦横小画面をスクリーンショットで確認し、表示の見切れは認めなかった。
- 操作：8倍速自動プレイで166秒、スコア23400・撃破125・被弾0のクリア。結果から再挑戦し、320×568へ切り替え、ポーズ・再開後に再び同じ結果でクリアした。画面変更中のCanvas解像度とゲーム進行を確認した。
- 音：ChromeでタイトルのSOUND OFF→ON→OFFの画面表示と `aria-pressed` の切替を確認。コンソールエラーは0件。音量と音色は聴いていない。
- 処理時間：開発用 `?profile=1` はプレイ中の更新・Canvas描画・HUD更新のJavaScript時間とrAFコールバック間隔を最大1500フレーム記録する。DPR 2・通常速度のChromeで1500フレームの平均0.28ms、95パーセンタイル0.50ms、rAF間隔95パーセンタイル9.0ms。DPR 1・横画面の8倍速再生1298フレームでは平均0.28ms、95パーセンタイル0.50ms、rAF間隔95パーセンタイル9.2ms。この計測は当該Chrome環境の値であり、入力遅延、GPU描画・合成時間、実機FPSを示さない。
- 未実施：実際のタブ離脱、物理端末の同時タッチとセーフエリア、別ブラウザ、聴感、入力遅延、GPU負荷、長時間の再挑戦、初見の有人プレイ。βとフェーズ08の完了判定は保留する。
