# 06 バーティカルスライスレビュー

## 06-01 デスクトップ代表区間（2026-10-09）

### 対象と狙い
`phase-06-01/` にフェーズ05から独立した、キーボードで遊べる約60秒版を保存した。最初の撃破から回収、バースト、ボスまでを対象に、視覚・音・HUDの品質目標を検証した。

### 実装・確認結果
- 戦闘イベントを状態更新から分離し、撃破の閃光と放射線、回収の輪と数値、被弾の赤い輪、バーストの拡大輪、切替の輪を追加。敵弾は演出より手前に描く。
- 低コントラストの宇宙港遠景、星、スクロールするグリッド、モード枠、5段階ゲージを追加。960×540の表示をChromeのスクリーンショットで確認し、自機・敵弾・回収物の形と色を識別できた。
- Web Audioの合成効果音を追加。初期状態はOFF。ChromeでON/OFFのボタン状態、プレイ中の切替、コンソールエラー0件を確認した。実際の音量・音色は聴感テスト未実施。
- 開発用の自動再生でボスを撃破し、約45秒、スコア10050、撃破37、被弾0のクリア画面を確認した。結果後の再挑戦操作は元の仕組みを維持している。
- `npm run typecheck`、`npm test` 10件、`npm run build` に成功。フェーズ05の8件も独立して残る。

### 体験と品質の判断
射撃モード、ゲージ、敵弾は遠景より明るく、情報の優先順位が保たれている。撃破と回収の反応は図形だけで再利用でき、コンテンツを増やす際も同じイベント経路を使える。音源ファイルがないため権利処理と読み込み待ちが不要な一方、音の質とバリエーションは今後の聴感確認で判断する。

自動再生の中盤で敵が途切れ、回収物だけが残る瞬間は残る。初見の人の難度、入力遅延の数値、フレーム時間、スマートフォン表示は未測定。フェーズ06全体のゲートは次スライス後に判定する。

### 制作手順と残作業
1. ゲーム更新から意味のあるイベントを発行する。
2. イベントを短い図形アニメーションと音へ割り当てる。
3. 危険物を最前面に保ち、ブラウザの通常操作と自動再生で確認する。

この手順は軽量敵、耐久敵、ボスの共通イベントに適用できた。残りはタッチ操作、縦持ち／横持ちのUI調整、有人プレイの難度・音量・入力遅延の評価。追加アセット制作の所要時間はまだ見積もれないため、フェーズ06-02後に再評価する。

## 06-02 モバイル代表区間（2026-10-09）

### 対象と確認結果
`phase-06-02/` を独立した成果物として保存した。仮想スティック、長押し射撃、切替、バースト、ポーズをキーボード入力と同じゲーム意図へ合成する。スティックと射撃は別々のポインターIDを保持するため、同時入力できる。解除・キャンセル・タブ離脱・ポーズ・リトライでは入力を消す。

ChromeでPC幅、390×844と320×568の縦持ち、844×390の横持ちをスクリーンショット確認した。縦持ちは画面下部に操作領域、画面直下に数値付きHUDを表示し、横持ちはゲーム画面の左右に操作領域を配置した。横持ちのボタンは最小48 CSS px、間隔8 CSS px。画面内でモード切替、ポーズ、再開、ゲームオーバー後の再挑戦を操作し、再挑戦時に残機・時間・モードが初期値へ戻ることを確認した。PC幅では既存のゲーム表示が保たれた。

Node 24で`npm run typecheck`、12件の`npm test`、`npm run build`が成功。CIにも06-02の同じチェックを追加した。スティックの強さと上限、タッチとキーボードの合成は自動テストで確認した。

### 品質判断と課題
危険物を描くゲーム画面から操作ボタンを離し、モード・残機・ゲージは小画面でも文字と数値で確認できる。縦持ちでは16:9のゲーム画面が小さくなるため、敵弾の細部や親指の使いやすさは実機で再評価する。横持ちは高さ390pxで収まるが、端末のセーフエリアとブラウザUIの差が残る。物理的な同時マルチタッチ、入力遅延、フレーム時間、音量・音色、初見プレイヤーのテンポと難度は未確認。これらはフェーズ08〜09の端末・有人検証で扱う。

### 制作手順と残りの規模
次のコンテンツも「ゲーム状態からイベント発行 → 共通の演出・音へ接続 → PCと縦横画面で確認 → 自動テストとCI」という手順を使える。現状は約60秒の代表区間で、MVPの約3分まで戦闘配置とテンポを増やす必要がある。残り約2分の配置、敵・ボスの行動の磨き込み、絵と音のバリエーション、難度調整をフェーズ07の主な作業と見積もる。実際の制作時間は有人プレイと素材制作の反復に依存するため、07-01の最初の区間で記録して更新する。

### フェーズ06受け入れ判定
**完了。** PCと小画面の品質目標、および残りの制作に使う実装・検証手順を確認できた。未確認の実機操作感と定量性能はフェーズ08〜09へ引き継ぐ。
