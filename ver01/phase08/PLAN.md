# フェーズ08 アルファ・ベータテスト計画

## 目的
MVPの主要フローと基本ルールをαテストで確かめ、操作性・表示・端末差・安定性をβテストで評価する。

## 完了条件
- 開始から結果・再挑戦までが破綻せず、リリースを妨げる重大な既知不具合がない。
- PCとスマートフォン相当の画面サイズ・入力を、AIによるブラウザ操作と自動テストで確認する。
- 発見した不具合を再現手順・期待動作・実際の動作・重大度つきで記録し、修正後に再確認する。

## AIのみで行う検証範囲
物理端末と友人・外部プレイヤーの協力を受け入れ条件から外す。画面サイズ、DPR、擬似セーフエリア、タッチイベント、キーボード、ブラウザ差、繰り返しプレイ、描画時間をAIが検証する。音はON/OFFと発音処理を機械的に確認する。実際の指先の使いやすさ、表示完了までの遅延、主観的な音量・楽しさは測定済みと扱わず、公開判断の制約として記録する。

## スライス
1. [x] `phase-08-01`：αテスト。主要フロー、結果確定、タブ離脱・再挑戦の安定性を確認し、再現した不具合を修正する。実際のタブ移動による自動ポーズを08-03で追加確認。
2. [x] `phase-08-02`：βテスト。AIによる操作性、表示・高DPI、入力から描画処理までの時間、音声機能、複数画面サイズを評価する。
3. [x] `phase-08-03`：Safariのブラウザ差とタブ離脱・復帰を確認する。08-10で実タブ切替の自動ポーズと再開、08の最終判定で保持キー中のフォーカス喪失を模擬して入力解除を確認。
4. [x] `phase-08-04`：ページ離脱時の中断と入力解除を確認する。押下中に離れるブラウザ操作はβテストへ残す。
5. [x] `phase-08-05`：開発環境で入力イベントからCanvas描画までの時間を計測する。
6. [x] `phase-08-06`：小画面のセーフエリアと操作領域を確認する。
7. [x] `phase-08-07`：非同期の音声切替と表示状態を確認する。聴感・音量は別途評価する。
8. [x] `phase-08-08`：複数回のステージ完走、再挑戦、タイトル復帰の状態を確認する。
9. [x] `phase-08-09`：フォーカスしたボタンのSpace操作とゲーム入力の競合を確認する。
10. [x] `phase-08-10`：タッチ操作ボタンのキーボード操作と同時入力を確認する。
11. [x] `phase-08-11`：ポインターキャプチャ喪失時に移動と射撃の保持入力を解除する。実ブラウザでのキャプチャ喪失は未確認。
12. [x] `phase-08-12`：満タン時のバースト準備完了表示をCanvasと小画面で確認する。実際の回収から満タンになる瞬間は未確認。
13. [x] `phase-08-13`：武器切替直後のモード名を表示し、連続切替と消滅を確認する。
14. [x] AIのみの条件で画面・入力・音声機能を再確認し、フェーズ08の受け入れ判定と残存リスクを記録する。

## 確認方法
各スライスで型チェック、テスト、ビルド、ブラウザ操作を行う。対象環境と合否、未実施の理由は `docs/08-qa-plan.md` に記す。

## 判定
AIのみの受け入れ条件を満たし完了。根拠と測定対象外の制約は `docs/08-acceptance.md` に記録した。
