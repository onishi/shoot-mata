# 02 製品要件

状態: Phase 02完了・製品ベースライン v1（2026-10-19）

## 1. 製品定義

ブラウザで遊べる、一人用の横スクロールシューティング。敵から得る3色のリアクターコアを取得順に3枠へ装填し、主武器、成長段階、補助特性を戦闘中に組み替える。4つの固有ステージを通したキャンペーンと、解放済みステージの単独プレイを備える。

完成とは、本書の必須要件と `02-acceptance-matrix.md` がすべて合格し、合格物と同一のビルドが本番で確認された状態を指す。内部MVP、バーティカルスライス、全ステージが存在するアルファを完成とは呼ばない。

## 2. 体験目標

| ID | 必須要件 |
| --- | --- |
| EXP-01 | 欲しいコアへ向かう危険と現在構成を守る安全が10秒単位で競合し、取得順に意味のある判断が生じる |
| EXP-02 | 3武器は射線、安全圏、得意な敵編成が異なり、単一構成が全区間の最適解にならない |
| EXP-03 | 被弾や失敗の理由と直前のコア列を理解でき、次の試行で変える行動が分かる |
| EXP-04 | 各ステージが異なる空間、仕掛け、敵編成、ボス、コア選択圧を持ち、色替えとして感じられない |
| EXP-05 | 90年代アーケード作品を思わせる即応性、密度、短い再挑戦を持ちつつ、固有名称・造形・音・ルールを複製しない |

## 3. コアループと状態遷移

| ID | 必須要件 |
| --- | --- |
| LOOP-01 | タイトルからゲーム開始、導入、操作説明、ステージ、ボス、結果、次ステージ、エンディングへ中断なく進める |
| LOOP-02 | 解放済みの各ステージを単独で開始し、導入から結果まで遊び、同条件で再挑戦またはステージ選択へ戻れる |
| LOOP-03 | プレイ中は移動、射撃、回避、敵撃破、コア選択、武器成長、得点が一つの循環として機能する |
| LOOP-04 | ポーズ、再開、ステージ再開、タイトルへ戻る操作があり、確認なしの進行喪失を防ぐ |
| LOOP-05 | 全4ステージのキャンペーン完了後に固有のエンディングと総合結果を表示し、再挑戦可能にする |
| LOOP-06 | ゲームオーバー時は直ちに同ステージを再挑戦でき、キャンペーンでは明示された条件のコンティニューを選べる |

## 4. 三連装リアクター

### 4.1 共通規則

| ID | 必須要件 |
| --- | --- |
| CORE-01 | コアは赤・青・黄の3種で、色に加えて形状と記号で取得前から識別できる |
| CORE-02 | 取得したコアは3枠へ古い順に並び、4個目で最古の1個を押し出す。取得前に押し出される枠を予測できる |
| CORE-03 | 先頭コアが主武器系統を決め、同色数1〜3がLv1〜3を決める。各段階は数値だけでなく機能と見た目が変わる |
| CORE-04 | 主武器と異なる色は補助特性を与える。混色には単色Lv3を崩す代償に見合う、状況依存の用途がある |
| CORE-05 | 被弾、ミス、コンティニュー時のコア喪失規則を一貫して表示し、回復不能な詰みを作らない |
| CORE-06 | 現在の3枠、先頭、武器系統、レベル、補助特性、次に押し出される枠をHUDと機体表現から判別できる |
| CORE-07 | コアの出現は敵種・区間予告と対応し、攻略を計画できる。制約付き変化を使う場合も必要色が長時間得られない状態を防ぐ |

## 6. 難易度、スコア、進行保存

| ID | 必須要件 |
| --- | --- |
| PROG-01 | 初回はキャンペーンの第1ステージを開始でき、クリアに応じて単独ステージ選択を順次解放する |
| PROG-02 | 標準難度に加え、敵弾・被ダメージ・救済を調整するアシスト設定を持つ。アシスト利用を罰する表現をしない |
| PROG-03 | スコアは敵撃破、危険を伴うコア取得、連続撃破または無被弾区間を反映し、結果画面で内訳を確認できる |
| PROG-04 | ステージ別・難度別のローカルベストスコアとクリア状態を保存する。外部共有やオンライン順位は必須にしない |
| PROG-05 | 保存データはversion付きで、破損・利用不可・将来の移行失敗時もゲーム開始を妨げない。初期化には確認を求める |
| PROG-06 | 標準難度は初見の学習余地を残し、各ステージで新要素を導入してから複合し、理不尽な初見殺しを予告で避ける |

## 10. 技術品質と対応環境

| ID | 必須要件 |
| --- | --- |
| TECH-01 | シミュレーションは描画頻度から分離した固定時間刻みで、長いdeltaとタブ非表示からの復帰時に暴走しない |
| TECH-02 | ステージ、敵編成、ドロップ、ボス段階をデータ駆動で追加・検査でき、4ステージが同じ巨大条件分岐へ密結合しない |
| TECH-03 | ユニット、統合、決定的な通しプレイを自動化し、各ステージの開始、固有要素、ボス、結果、遷移を検査する |
| TECH-04 | リリース候補をChrome、Edge、Firefoxで検証し、PC・縦長・横長とkeyboard／Pointer Eventsを確認する。Safari desktopとiOS Safari・Android Chrome実機は利用可能な場合に追加検証し、未実測は残存リスクとして記録するが進行blockerにしない |
| TECH-05 | 開発機上の再現可能な高負荷条件で、目標fps、入力応答、進行速度、5分以上の停止・資源傾向を検証する。物理低性能実機は利用可能な場合に追加測定し、未実測は残存リスクとして記録するが進行blockerにしない |
| TECH-06 | 主要フローで未処理例外、コンソールエラー、欠落アセット、意図しない外部通信を0件にする |
| TECH-07 | ビルド容量、初回ロード時間、メモリ傾向をリリースごとに記録し、Phase 05で定める予算内に収める |
| TECH-08 | 依存関係の既知脆弱性を監査し、重大・高リスクを0件にするか、影響と期限付き対応を最終検収で明示する |

## 12. 内部MVP

内部MVPはPhase 05の技術基盤を検証する一時的な部分集合であり、製品完成条件ではない。

含むもの:

- 仮の1区間での移動、射撃、敵、被弾、結果
- 3色コアのキュー、3主武器のLv1〜3を機能検証できる仮表示
- キーボードと基本タッチ入力、固定時間刻み、音声開始、例外安全な保存
- データ駆動の仮ステージと決定的テスト

含まないが製品には必須のもの:

- 4つの完成ステージと全ボス、キャンペーン、エンディング
- 完成アート、全アニメーション、全BGM・効果音、最終UI
- 全画面サイズ・ブラウザ・アクセシビリティ・性能の製品検証
- 難易度曲線、全体ポリッシュ、権利監査、本番公開、ロールバック

MVPの合格は `02-acceptance-matrix.md` の製品状態を合格へ変更しない。

## 13. 完成判定

Phase 10で次をすべて満たすまで製品完成としない。

1. 受け入れマトリクスの全必須IDが合格し、証拠へ追跡できる。
2. 4ステージをキーボードとタッチで開始から結果まで確認し、キャンペーンをエンディングまで複数回完走する。
3. アセット台帳の必須素材がすべて `final` かつゲーム内で `verified` であり、仮素材が残っていない。
4. 重大な既知不具合が0件で、残存する低リスク事項と未確認の主観評価を明記する。
5. Phase 11で同一ビルドの本番スモーク確認とロールバック準備を完了する。

Safari desktop、iOS／Android実機、物理低性能実機の未実測は、2026-10-26のユーザー指示により上記1〜4の不合格条件には含めない。対応を保証したという意味ではなく、未確認環境とリスクをリリースノートへ残す。
