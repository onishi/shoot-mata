# 04 アートディレクション

状態: Phase 04進行中（2026-10-21）

## 基準シーン

`assets/concept/stage-01-orbital-wreck-benchmark-v1.png` を、軌道残骸帯の素材感、奥行き、照明、シルエット密度の初期基準にする。これは構想用の一枚絵であり、ゲーム投入可能な背景、自機、敵、コアへ分離されていないため状態は `draft` とする。

## 視覚言語

- 舞台: 深い藍と炭色を基調に、艦骸内部の琥珀灯とエンジンのシアンを機能色として使う。
- 自機: 左から右へ尖る三角形の前進シルエットと、後部の3セル発光部で敵と区別する。
- 敵: 円筒・球体を基礎に、橙赤の単眼と右向き噴射を持たせる。自機と同じ三角前進形を避ける。
- コア: 赤=ひし形+`I`、青=円+`+`、黄=三角+`◎`。色が失われても外形と内部記号が重複しない。
- 背景: 遠景の惑星・艦隊、中景の艦骸、前景の暗い梁を別速度で動かせる3層以上に分ける。中央の飛行回廊は背景ディテールを抑える。
- 質感: 塗装金属、露出トラス、焦げたセラミックを使い、均一なネオン面や基本図形だけの表現を完成素材にしない。

## 戦闘可読性

- 自機と味方弾はシアン系、敵と敵弾は橙赤系を起点にするが、色だけには依存しない。
- 敵弾は閉じた円、味方弾は進行方向へ伸びる線または鏃、コアは固有外形と内部記号を必須とする。
- 背景の中央回廊は戦闘対象より低い局所コントラストに抑え、危険物の輪郭線と同じ太さ・明度を使わない。
- 動き軽減時はカメラ揺れ、前景速度、粒子数を減らすが、警告、攻撃方向、被弾、回収結果は残す。

### 機械検査の基準

- 自機、敵、3コアは64×64へ正規化し、グレースケール、1型・2型・3型色覚シミュレーション後の同一分類内の平均画素差を18/255以上にする。
- 中央回廊に使う遠景の水平輪郭密度は、同条件の自機・敵より低くする。代表素材の実測は背景3.82、自機6.04、敵7.76。
- 味方弾は右向き鏃、敵弾は閉じた円とし、外形、内部、移動方向を合わせた非色シグネチャを重複させない。
- 明滅は3回/秒以下、通常時のカメラ揺れは横1.5%・縦1.0%・1回350ms以下を上限とする。動き軽減時のカメラ揺れは0とし、静止した形状情報を残す。
- 現在の代表VFXは命中1.11回/秒、被弾0回/秒、回収0.91回/秒。回転や拡縮を明滅回数へ水増しせず、輝度パルス数を継続時間で割って判定する。

## UI

- HUDは3枠を古い順に左から表示し、先頭枠を寸法と輪郭の両方で強調する。
- 次の取得で押し出される枠と、取得後の主武器・Lv・補助を操作前に表示する。
- ゲーム画面内の常設HUD遮蔽率は面積12%以下を初期上限とし、ボス警告など一時表示は別計測する。
- タッチ対象は44 CSS px以上、本文相当文字は12 CSS px未満にしない。縦長ではゲーム比率を保ち、操作領域を下へ分離する。

## 音の方向

- BGMはステージ固有のリズム層、旋律層、危機層へ分離可能な構成を想定する。
- 赤ランスは短い硬質インパルス、青スプレッドは帯域の広い複数発、黄シーカーは発射と捕捉を分ける。
- コア回収、装填、押し出し、Lv上昇を異なるイベントとして実装できる命名にする。
- 完成判定はクリップ、ピーク、無音余白、ループ端、ファイル欠落を機械検査する。音色や快さの主観評価は行わない。

### 書出しと波形基準

- 編集・検査用マスターは48kHz、mono、PCM16 WAVとし、配信用形式と圧縮率はPhase 05の実ブラウザ計測で決める。
- ファイル名は`役割-イベント-v番号.wav`とし、武器系は`weapon-{lance|spread|seeker}-...`、コア系は`core-...`、UIは`ui-...`、ステージ層は`stage-{番号}-{層}-loop-...`を使う。
- 武器発射はピーク−9〜−5dBFS、コア通知は−10〜−6dBFS、UIとBGM層は−13〜−11dBFSを代表範囲とする。最終ミックス時には同時発音数を含めて再調整する。
- クリップ0、−60dBFS基準の先頭無音10ms以下・末尾無音30ms以下、ループ端の正規化振幅差0.01以下を自動検査する。
- 生成式と乱数をコードへ固定し、外部サンプルを混ぜない。外部素材を後から採用する場合は台帳へ出典、許諾、編集履歴を追加する。

## 未確認

懐かしさ、新しさ、迫力、美しさ、音の快さ、長時間プレイ時の疲労は人間による主観評価を実施していない。色覚シミュレーションは近似変換であり個人の見え方を保証しない。後続の客観検査結果をこれらの代替証拠にはしない。
