# Phase 03 plan — コアメカニクス試作

状態: 進行中（2026-10-19）

## 目的

移動、射撃、敵、パワーアップを同じ短い戦闘条件で操作できるようにし、最低3案を判断の面白さ、視認性、成長実感、入力負荷で比較する。Phase 01で採用した三連装リアクターも反証可能な仮説として扱う。

## 比較する3案

1. FIFO三連装: 3枠へ取得順に装填し、最古色が主武器、同色数がレベルになる。4個目で最古を押し出す。
2. 独立兵装庫: 色ごとのレベルを永続的に蓄積し、最後に取った色へ自動で切り替える。
3. 連鎖過給: 最後に取った色が主武器になり、同色連続取得だけがレベルを上げ、異色でLv1へ戻る。

3案は同じ敵、ドロップ、移動、オート射撃を使う。入力差ではなく、取得判断と状態理解の差を比較する。

## 対象

- レスポンシブなブラウザ比較プロトタイプ
- 赤・青・黄の3武器と各Lv1〜3の機能差
- キーボード・Pointer Eventsによる移動
- 固定シードの敵・ドロップ列、45秒セッション、比較指標
- 状態遷移のユニットテスト、実ブラウザ操作、PC・縦長・横長の画面確認
- 比較結果と採用・修正・棄却の判断

## 対象外

- 製品用コード、最終技術スタック、完成アート、完成音
- ステージ、ボス、キャンペーン、保存の製品実装
- 自動計測だけによる「面白い」の判定

比較ログUIと3回ずつの進捗表示は実装済み。別端末・別ブラウザの公式JSONを検証して統合でき、重複と方式ごとの3件超過は記録へ混ぜない。同じ完走の正式／QA区分が別端末で変わっても、区分以外のセッション内容で重複を検出する。320×844のChrome表示は確認済みだが、実タッチ端末と別ブラウザが未確認のため画面条件は未完了のままとする。

正式比較の環境情報からPC、320〜390px縦長、スマートフォン横長、キーボード、実タッチを集計し、比較ログと公式JSONへ出力する。途中で画面サイズを変更した完走は単一画面条件の証拠へ数えない。3案×各3回と5つの環境条件を別々に表示し、9完走だけでレビュー準備完了とはしない。

正式比較は画面に表示する条件IDが同じビルドだけで行う。敵・コア列、武器値、補助効果、セッション時間など定量・主観結果へ影響する条件を変更した場合は条件IDも更新し、変更前後の完走を統合しない。公式JSON、各完走、ブラウザ保存キーへ同じ条件IDを記録し、異なる条件IDの読込は全体を拒否する。

QA・導線確認の完走は証拠として保存しつつ、正式な進捗、次方式の推奨、方式別集計から除外できる。既存記録も個別に正式／QA除外を切り替えられ、メモだけに依存して検証記録を判別しない。区分確認情報を持たない旧記録は `旧記録除外` として集計へ入れず、正式記録だと確認できる行だけを明示的に戻す。

現行形式の正式比較には、セッション中に実際に記録されたキーボード、マウス、タッチ、ペンのいずれかを必須とする。入力なしの自動進行はQA記録としてのみ保存でき、後から正式比較へ切り替えられない。環境情報追加前の旧記録は一律に無効化せず、既存の区分確認手順で扱う。

正式比較への切替でも方式ごとの3件上限を守る。上限到達後のQA記録は証拠として保持するが、正式化操作を無効にして4件以上の平均へ変わらないようにする。

比較順は慣れと疲労が一方式へ偏らないよう、`A→B→C / B→C→A / C→A→B` を画面で案内する。JSON出力には生の完走記録に加え、方式別の定量値・主観値の平均と3回完了判定を含める。平均値だけで採用を自動決定せず、自由記述と操作直後の観察をレビューする。

FIFO案の異色補助は、混色価値を実操作で比較できるよう赤=貫通、青=防御、黄=回収の仮効果まで実装済み。これは完成版仕様の確定ではなく、3案×3回の比較で強度と選択価値を検証する対象とする。

## 確認方法

1. `node --test prototype/tests/*.test.mjs` で3案の状態遷移を検査する。
2. 固定シードと同じ難度で、画面に示す `A→B→C / B→C→A / C→A→B` の順に各案を3セッション操作する。
3. 結果の回収数、武器変更、Lv3滞在、撃破、被弾と、迷い、予測可能性、再試行意欲を別欄で記録する。
4. 1440×900、390×844、844×390相当でスクリーンショットと実操作を確認する。
5. 自動操作は進行不能・例外検出にだけ使い、面白さの証拠にはしない。
