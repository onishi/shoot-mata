# Phase 05 plan — 技術基盤

状態: 進行中（2026-10-21）

## 目的

単一の `ver02/game/` に、4ステージと製品全体をデータ駆動で追加できる実行基盤を作る。内部MVPの仮区間を使い、固定時間刻み、状態遷移、入力、音声、保存、ステージデータ、描画、テスト、静的ビルドを端から端まで接続する。

Phase 05の成果物は技術基盤であり、完成製品、完成アート、バーティカルスライスとは扱わない。人間の楽しさ、操作感、聴感は進行ゲートにせず、未評価として残す。

## 対象

- 描画頻度から独立した固定時間刻みと、長いdelta・非表示復帰の安全化
- タイトル、説明、プレイ、ポーズ、結果、再挑戦を扱う明示的な状態遷移
- キーボードとPointer Eventsを共通コマンドへ変換する入力抽象化
- START操作後の音声初期化、音量・ミュート、失敗時の無音継続
- version付きローカル保存、破損・利用不可・旧versionの安全な退避
- schema検査付きのステージ、敵編成、ドロップ、ボス段階データ
- Phase 04の同一アセットを参照するCanvas描画とレスポンシブUI
- unit、integration、決定的通しプレイ、ブラウザ検査の実行入口
- 依存を最小化した再現可能な静的ビルドとCI

## 対象外

- 第1面を完成品質へ仕上げること（Phase 06）
- 残り3面と全製品素材の量産（Phase 07）
- 製品全体の難易度調整、主観的な操作感・聴感の合否
- 本番公開とリリース判定

## 実装順

1. 固定時間刻みと非表示復帰の安全化（TECH-01）
2. 状態遷移と決定的なゲームモデル（LOOP-04、CORE-05）
3. version付き保存と進行・設定モデル（PROG-01〜05、REL-02〜03）
4. 入力抽象化とアクセシブルな画面外UI（INP-01〜03、A11Y-04）
5. 音声初期化と無音継続（A11Y-01、AV-06）
6. ステージschemaと仮区間（TECH-02）
7. Canvas描画、レスポンシブ画面、フルスクリーン（UX-01〜07）
8. 統合・通し・性能・通信・依存監査と静的ビルド（TECH-03〜08）

## 確認方法

1. 純粋なモデルと境界アダプターをNode unit testで検査する。
2. 仮ステージをseed固定の自動入力で開始から結果まで完走する。
3. 実ブラウザでキーボードとPointer Events、音声失敗、保存失敗、visibility遷移を操作する。
4. PC、縦長、横長の画像、console、network、performance計測を証拠として残す。
5. 受け入れマトリクスはPhase 05だけで最終合格にせず、実装中または後続再検証として更新する。
