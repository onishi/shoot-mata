# Phase 08 plan — コンテンツ完成アルファ

状態: 進行中（2026-10-24）

## 目的

Phase 07で揃えた4面と全主要システムを、製品入口から複数回通して検証する。進行不能、状態初期化、保存、操作、レイアウト、音、性能の不具合を検出・修正し、不足する必須情報を製品UIへ接続する。

## 対象

- 被弾・敗北理由、直前コア列、再試行で変える行動の表示
- 各面の単独開始、結果、再挑戦、キャンペーン遷移、コンティニュー
- 保存復元、破損・拒否時の縮退、設定反映
- キーボード・Pointer Events、ポーズ・復帰、PC・縦長・横長レイアウト
- 無音完走、欠落asset、console、外部通信、オフライン相当の静的実行
- 複数seedの全4面・キャンペーン通しとアルファ不具合台帳

## 対象外

- 主観的な楽しさ、操作感、聴感を機械検査だけで合格とすること
- 最終難易度、全ブラウザ・実端末、長時間性能の最終調整（Phase 09）
- 製品要件の最終検収と本番公開（Phase 10〜11）

## 実装順

1. [完了] EXP-03として、敗北原因、直前コア列、失った状態、原因別の再試行ヒントをGAME OVERへ接続する
2. [完了] LOOP-02/04/06として、4面の単独再挑戦・離脱確認・キャンペーンコンティニューを通す
3. [完了] PROG-01/03/04/05とREL-03として、実4面の保存復元、best、異常系、接続喪失相当を検証する
4. UX-01/05/06/07、INP-01/02/04、A11Y-01/04を3画面条件とブラウザ操作で再検証する
5. TECH-01/03/06/07として複数回キャンペーン、無音、resource、console、容量、短時間性能を記録する
6. 受け入れマトリクス、開発ログ、既知不具合とPhase 09への残存リスクを更新する

## 完了条件

- [ ] 4面を単独・キャンペーン双方で開始から結果・再挑戦まで複数回完走できる
- [ ] 敗北画面で原因、直前コア列、喪失、次に変える行動を確認できる
- [ ] 保存、設定、ポーズ、復帰、コンティニュー、入力切替で進行不能がない
- [ ] PC、320〜390px縦長、横長で主要情報と操作が欠落しない
- [ ] 無音・保存拒否・接続喪失相当でも保存済みデータを破壊せず完走できる
- [ ] build、asset、console、外部通信、短時間性能のアルファ検査に合格する
- [ ] 重大な既知不具合とPhase 09へ残す未確認事項が証拠付きで記録されている

## 最初の作業単位

[完了] EXP-03の敗北診断を実装した。被弾直前のコア列と残機、被弾理由、失ったコアをsimulation snapshotへ保持し、敵弾・接触・全ステージ固有危険・時間切れに対応する原因表示と再試行ヒントをGAME OVERへ接続した。`?qa=failure-review`で敵弾敗北をtick 939に再現し、原因、無武装列、残機1→0、再挑戦を確認した。320×844、390×844、844×390でoverflow 0、console warning/error 0。320pxで長文がdialog外へはみ出す不具合を検出し、縦長時だけ敗北dialogをviewport内modalへ変更して修正した。

LOOP-02/04/06は、実4面それぞれの単独開始→敗北→再挑戦→2回の同seedクリア一致→ステージ選択復帰、実第4面の確認付き再開始・タイトル離脱、キャンペーンの2回限定コンティニューを同じapplication経路で検査した。単独敗北画面に押すと例外になるコンティニューボタンが表示される不具合を修正し、Chromeで単独第4面とキャンペーンの残数2→1→0を確認した。

PROG-01/03/04/05とREL-03は、実4面の標準best・内訳・最終コア列と第4面アシストbestを同一storageへ保存し、別repository/applicationから復元した。ステージ選択と結果へ現在難度のbestを表示し、Chrome campaign完走後と通常URL再読込後に4面bestを確認した。破損・取得／読込拒否はrepository、書込拒否は実第1面の結果までapplicationで注入した。配信サーバー停止中も読込済み第4面を開始でき、音声欠落は警告付き無音へ縮退し、サーバー復帰後も保存bestは不変だった。
