# Phase 12 plan — 運用

状態: 完了（2026-10-26）

## 目的

公開済みv2.0.0を固定リリースとして監視し、障害、互換性、性能、依存関係、権利条件、改善要望を同じ優先順位規則で管理する。未実測環境や主観品質を合格済みに読み替えず、利用可能になった証拠だけを追加する。

## 対象

- 本番URLと全配信ファイルの継続的な同一性監査
- 依存関係と公開workflowの定期検査
- 障害レベル、初動、ロールバック、修正版公開の手順
- Safari、実モバイル、物理低性能実機、生成物権利、将来互換性の残存リスク
- 修正、改善、新機能候補の優先順位付き運用台帳

## 非対象

- Phase 10固定RCの内容を運用準備だけで変更すること
- 未実測環境、楽しさ、操作感、聴感、美しさを確認済みとすること
- 外部分析、Cookie、サーバー保存、常駐監視サービスの追加
- 不足コンテンツを運用項目へ降格すること

## 作業単位

1. [x] 運用台帳、障害・更新runbook、fail-closed監査、定期production workflowを追加する。
2. [x] 定期workflowを既定branchで実行し、本番同一性と依存監査の初回runを記録する。
3. [ ] 利用可能な実環境が増えた場合だけ、同じ公開buildで互換性・性能証拠を追加する。
4. [x] 権利条件の定期確認と改善要望のtriageを実施し、台帳へ履歴を残す。
5. [x] 監視と更新手順が実運用で動作した証拠をreviewへまとめる。

## 完了条件

- 本番artifact監査と依存監査が定期実行され、失敗がGitHub Actionsの失敗として可視化される。
- 障害の重大度、初動、固定v1.0.0へのrollback、修正版の再検収手順が一意に参照できる。
- 互換性、性能、依存関係、権利、改善要望が優先順位、状態、trigger、対応手順付きで管理される。
- 未実測リスクを証拠なしで解消済みにできず、公開version・build・manifestの不一致を監査が拒否する。

## 確認方法

`ver02/game`で`npm run audit:operations`、`npm run audit:production`、`npm run verify`を実行する。定期workflowは同じ固定buildを再現した後に運用台帳、本番全ファイル、high以上の依存脆弱性を検査する。外部状態を変更するrollbackや修正版deployは、自動実行せず`OPERATIONS.md`の確認手順に従う。
