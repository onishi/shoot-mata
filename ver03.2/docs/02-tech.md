# 02 技術設計

状態: M4完了（全6面・エンディング・ステージ練習・性能検証・自動公開完了、2026-10-27）

## 構成

- `ver03.2/game/src/core/`: 60 tick/秒で動くブラウザ非依存のゲーム規則。
- `ver03.2/game/src/content/`: ステージ、物語、地形、敵編成のデータ。
- `ver03.2/game/src/browser/`: Canvas描画、キーボード入力、`requestAnimationFrame` の薄い接続層。
- `ver03.2/game/tests/`: Nodeの単体テストと、PC版Chromeを実際に起動する通しテスト。
- `ver03.2/game/dist/`: `npm run build` が生成するGitHub Pages公開物。Gitには含めない。

外部フレームワークは使わず、ES ModulesとCanvas 2Dで作る。ブラウザ検証だけに`playwright-core`を使い、実行環境に入っているGoogle Chromeを起動する。

## シミュレーション

- 論理解像度は1280×800。`y < 720`がプレイフィールド、`y >= 720`がHUD専用帯。
- ゲーム規則は1/60秒の固定tickで進め、描画フレームと切り離す。
- ステージ内の時刻、敵出現、地形移動、ボス形態はtickで定義する。`src/content/stages.mjs` がキャンペーン順とステージ別地形参照をまとめる。各面はデータ上でも introduction / development / climax / boss の4区間と固有敵4種を持つ。Stage 5の敵弾反射も弾と`reflective-crystal`の同じ固定tick衝突で決定する。
- 通常実行は経過時間を蓄積して最大5 tick/フレームまで追いつく。タブ復帰時の巨大な遅れは捨てる。
- ミス時は最後に通過した面データ上のチェックポイントへtickとスクロールを戻し、その区間の敵、直前の立て直し用コア、破壊可能地形を同じデータから再構築する。残機が尽きた場合はチェックポイントへ戻さずCONTINUEへ遷移する。
- テスト用の`?autoplay=1`は同じtick関数へ決定的な自動入力を渡す。`?speed=N`はtick消化数だけを増やし、規則は変えない。
- クリア済み面の最大番号をlocalStorageへ保存し、タイトルのステージセレクトから単独練習できる。Stage 6はStage 5クリア後に解放し、練習結果からは次面へ進まずタイトルへ戻す。
- タイトルのAキーで標準 / アシストを切り替える。アシストは残機4、敵弾の移動量75%、コア回収半径1.25倍、復帰後無敵180tickとし、地形接触の規則とステージ内容は標準から変えない。難易度はキャンペーン、ステージ練習、コンティニュー、タイトル帰還をまたいで維持する。
- プレイ中のPキーでシミュレーションを停止し、ポーズ中はPで再開、Escapeでタイトルへ戻る。フォーカス喪失時も入力を解放して同じポーズ状態へ入る。
- 進行、ハイスコア、操作説明の既読、音量設定の保存は任意機能とし、ブラウザがlocalStorageを拒否しても既定値でゲームを継続する。ハイスコアは得点獲得時に更新し、キャンペーン、練習、コンティニュー、タイトル帰還をまたいで維持する。

## 地形

地形はステージのワールド座標にある矩形配列として定義する。描画、接触判定、自動操縦の安全路計算は同じ配列と`visibleTerrainFor()`を使う。背景画像とは別レイヤーで、危険な輪郭を明るく描く。Stage 1は固定梁と破壊可能な残骸壁、Stage 2は90tick予告後に閉じるシャッターと上下移動壁、Stage 3は開閉膜、収縮通路、破壊可能な嚢胞、Stage 4は90tick予告の熱波、回転壁、溶融床、破壊可能な遮蔽板、Stage 5は反射結晶、移動結晶壁、90tick予告の凍結ゲートを同じインターフェースで扱う。予告形状は描画と安全路計算には使うが、実体化前は接触判定を持たない。

## 音

- `src/browser/audio.mjs` がWeb AudioのBGM/SFX別gain、3レイヤーBGM、同時発音制限、ダッキング、マスターリミッターを管理する。ゲーム規則は音を直接再生せず、固定tickのカウンタと状態遷移を音側が読む。
- 初期値はBGM 65%、SFX 45%。タイトルのSOUND SETTINGSで5%刻みに個別変更し、ブラウザへ保存する。
- Stage 1の通常BGMはrhythmとmelody、150秒以降とボス戦はdangerを足す。3秒周期を共有し、追加レイヤーは既存レイヤーと同じ再生位置から始める。
- 同じSFXは4音、爆発は6音までとし、超えた場合は古い音を止める。WARNINGとミスはBGMを最大3dB、500msだけ下げる。出力直前に-1dBFSのリミッターを置く。
- `scripts/audit-audio.mjs` が配信WAVのPCMを読み、素材gainと初期設定を含めたRMS・ピークを検査する。不足する短い効果音は`generate-audio.mjs`で決定的に再生成できる。

## 自動検証

`npm run verify` は順に次を実行する。

1. 静的公開物を`dist/`へ生成する。
2. Node単体テストで固定tick、PULSE、地形接触、Stage 1完走を確認する。
3. 音素材のRMS・ピーク、常時射撃とBGMの相対音量を数値検査する。
4. ローカルHTTPサーバーとPC版Google Chromeを起動し、タイトルから実装済み全ステージの結果まで自動操縦で通す。
5. Canvasの論理領域、HUD分離、地形数、PULSE発射、各ボス撃破、音素材の読込と面別レイヤー遷移、実行時例外なしをブラウザ側の状態で確認する。
6. 最も描画負荷の高いStage 6ボス戦で更新と描画に使う実処理時間を3秒間測り、75フレーム以上、95パーセンタイル8ms以下、最大25ms以下を確認する。仮想環境の画面更新周期に左右されるフレーム間隔は診断値として記録し、60fpsの16.7ms枠に対してゲーム処理側の余裕を判定する。

画面変更時は通しテストが保存するスクリーンショットを画像として確認する。スクリーンショットは再生成物なのでGitには含めない。

## ビルドと公開

ビルドはHTML、CSS、`src/`をそのまま静的配信用に複製する。`main`へのpush時だけGitHub ActionsでNode/npmを固定し、`npm ci`と`npm run verify`が成功した`dist/`をGitHub Pagesへ公開する。手動確認入力と定期本番監視は使わない。
