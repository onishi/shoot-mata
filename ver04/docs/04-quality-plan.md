# Quality Plan

## 1. 品質方針

テスト数ではなく、プレイヤー体験と完成ゲートを証明する。規則は高速な決定的テスト、接続はChrome、読みやすさと演出は実画像、面白さは複数自動操縦の計測と実プレイ相当の批評を組み合わせる。

不具合修正には同じ入力・seedで失敗する回帰テストを先に、または同じ変更内で追加する。検査値を満たしても画像やプレイが悪ければ合格にしない。

## 2. M1の仮説ゲート

3分プレイグラウンドを次の3操縦で各10seed実行する。

| 操縦 | 方針 | 期待する差 |
| --- | --- | --- |
| Safe | 小輪、早いRETRACE、生存優先 | 被弾最少、撃破は遅い |
| Stitch | 小〜中輪と添え書きを頻繁に使う | 安定した撃破時間、閉路数最多 |
| Sweep | 大輪へ敵弾を集めて一括反撃 | 分散が大きいが成功時の得点最高 |

M1合格条件:

- 3操縦すべてが180秒を停止・詰みなしで完走する。
- 同一seed・入力列の状態ハッシュが5回一致する。
- 各操縦の中央値で3回以上の有効COLLATEがある。
- StitchまたはSweepが通常射撃のみより代表大型敵を20%以上速く倒す。
- Safeの被弾中央値がSweep以下、Sweepの得点中央値がSafe以上となる。
- COLLATE候補の誤点灯、画面外閉路、線上弾の不定判定が単体テストで0件。
- Chromeで移動、射撃、COLLATE、RETRACE、ポーズが操作でき、画像上で自機・敵弾・航跡・候補を識別できる。

値を満たさない場合はルールまたは仮説値を調整し、失敗もlogへ残す。単にテスト期待値を現状へ合わせない。

### M1-02実測結果（2026-10-31）

10seed、各180秒で通常射撃基準を含む4操縦を測定し、`docs/evidence/m1-02-autoplay.json`と`.md`へ全40走行を保存した。

| 操縦 | 有効COLLATE中央値 | 被弾中央値 | 得点中央値 | 最初の大型撃破tick中央値 |
| --- | ---: | ---: | ---: | ---: |
| 通常射撃 | 0 | 34.5 | 10,000 | 3,045 |
| Safe | 16.5 | 43 | 20,377 | 未撃破 |
| Stitch | 13 | 64 | 37,582.5 | 2,159 |
| Sweep | 11 | 53.5 | 37,739.5 | 2,271 |

- 40走行すべてが21,600tickを完走し、同一Stitch入力の最終hashは5回とも`682b5bd373fcb29e`で一致した。
- Stitchは通常射撃より最初の大型を29.1%早く撃破した。
- SafeはSweepより被弾が少なく、Sweepは3方式中で得点が最大となった。
- 初回値では閉路の移動機会費用を火力が回収できなかったため、印への添え書き威力を9から28、反撃片を8から16へ調整した。大輪の得点差も面積/100から面積/15へ拡大した。
- Safeは通常射撃基準より被弾が8.5多い。正式ゲートの役割差は成立したが、M2では敵構成を減らさず小輪後の回避余地を画面プレイで再評価する。

## 3. 自動テスト

### 単体

- 固定tick、accumulator上限、ポーズ停止、seed付き乱数。
- 航跡追加・期限切れ・線分交差・単純環・符号付き面積。
- 点が輪の内側、外側、辺上、頂点上にある場合。
- 捕捉上限、距離とIDの安定順、不可消去弾。
- 添え書き1回制限、印倍率、撃破イベント。
- RETRACEの弧長、ゲージ不足、画面端、地形内終点。
- 被弾無敵、耐久0、チェックポイント、コンティニュー。
- 欄外注の組合せと選択候補、全候補到達可能性。
- 保存の正常、破損、未知版、quota拒否、設定だけの復元。
- 状態遷移、blur自動ポーズ、押下キー解除。

### 統合

- 3分、各ステージ、全キャンペーンを高速simulationで完走。
- 全24敵が出現・攻撃・退場し、全6ボスの全形態へ到達。
- 出現表に30tick以上の意図しない無戦闘時間がない。
- entity上限超過、NaN、画面外永久生存、到達不能チェックポイントがない。
- 同じ入力リプレイの最終hash、スコア、被弾、撃破順が一致。

### Chrome E2E

- 初回起動、操作説明、設定、NEW VOYAGE。
- キーボード全操作、ポーズ・復帰、タブ非表示復帰。
- 1面開始から結果、コンティニュー、保存再読込。
- タイトルから6面・最終ボス・エンディングへの安定通し。
- localStorage拒否環境で警告後も完走。
- 1280×720、1440×900、1920×1080、devicePixelRatio 1/2でレイアウト逸脱なし。

## 4. 自動操縦と計測

simulationは1tickごとに以下を集計し、JSONと人間向けMarkdownを出力する。

- 面別・区間別の所要tick、被弾、コンティニュー、地形接触。
- 敵別の出現、撃破、退場、生存tick、攻撃回数。
- 同時敵数・敵弾数の平均、p95、最大、無戦闘時間。
- 閉路候補、有効/空/不発COLLATE、面積・周長、捕捉弾数。
- 添え書き弾率、印への命中、RETRACE回数・回避成功・地形失敗。
- 欄外注の提示・選択・構成別の火力、生存、攻略時間。
- ボス形態別時間、固有弱点成功、攻撃別被弾。

完成調整では各難易度30seed以上。通常クリア操縦の総時間15〜25分、意図しない無戦闘時間4秒未満、ボス1形態が全戦闘時間の45%を超えないことを基準にする。

自動操縦は面の正解を直接知る万能AIにしない。視界内の危険と短期目標だけを使い、固定入力リプレイ、反応遅延6〜18tick、位置誤差を持つ。攻略不能を隠すチート移動や無敵を禁止する。

## 5. 画像検査

画面・演出を変更した回は、実ChromeからPNGを採取し、AI自身が画像として確認する。数値やDOMだけで画面品質を合格にしない。

必須画像:

- タイトル、ガイド、設定、ポーズ、欄外注選択、コンティニュー、結果、エンディング。
- 各面の導入、通常戦、固有環境、山場。
- 全6ボスの各形態と弱点成功瞬間。
- 最小輪、最大実用輪、対象なし候補、敵弾捕捉、添え書き、RETRACE、被弾。
- 最重負荷と3解像度のHUD。

目視項目は、危険の判別、候補の理解、当たり判定との一致、文字切れ、背景の反復、仮素材、爆発による隠蔽、配色以外の面差、ストーリー変化。画像パスと所見を面別レビューへ記録する。

視覚回帰は安定するHUDとレイアウトに限定し、粒子差で全画像を無意味に失敗させない。ゲーム画面は固定seed/tickで採取する。

## 6. 音量監査

素材ごとにサンプルレート、チャンネル、無音、長さ、RMS、true peak相当を検査する。実ミキサで射撃連打、最大18弾捕捉、被弾とボス攻撃、UI連打の最悪ケースをオフラインレンダーする。

合格基準:

- 出力ピーク -1.0 dBFS以下、NaN/clip 0 sample。
- BGMとSEを個別0にしても他方が鳴る。
- 設定0ではbus出力が-90 dBFS未満。
- 同一SEの同時数と総ボイス上限を超えない。
- 重要予告が標準BGM中にRMS差または帯域差で識別できる。

## 7. 性能ゲート

対象はPC Chromeのヘッドレス計測と可視Chrome確認。最重負荷の固定リプレイを60秒、ウォームアップ10秒後に採る。

- simulation 1 tick: 平均0.8ms以下、p95 1.5ms以下、最大4ms以下。
- 1表示frame（CPU）: 平均8ms以下、p95 12ms以下、最大25ms以下。
- 60秒中50ms超long task: 0回。
- entity上限時も入力から次回描画まで50ms未満。
- 10分通し後のJS heap増加が安定区間比15%未満。

CI環境差を考慮し、絶対値と直近合格値からの25%以上の悪化を両方検出する。負荷を隠すために敵や弾を黙って消さず、生成拒否はカウンタで失敗させる。

## 9. マイルストーン判定

- M1: 2節の仮説ゲートを満たす3分試作。仮素材を台帳で追跡。
- M2: Stage 1を開始から結果まで完成素材・音で通し、制作規格と監査を確定。
- M3: 6面、24敵、6ボス、全成長、最終戦、EDを自動・Chromeで完走。
- M4: 画像、音量、性能、保存、難易度、公開を含むルートREADMEの完成ゲート全件合格。

ゲート未達のまま次へ進まない。値の例外化は、要件を縮小せず、測定方法の欠陥を証明した場合だけ設計変更として記録する。
