# 技術設計

最終更新: 2026-11-03

## 構成

- TypeScript + Vite、外部ランタイムライブラリなし
- `src/model.ts`: 決定的な盤面規則。DOM、時刻、音声へ依存しない
- `src/main.ts`: 入力、画面遷移、Canvas描画、Web Audio
- 固定入力単位のターン制。描画の経過時間は規則へ影響しない

## 状態

`GameState`は画面、現在拍、現在入力、過去2フレーズ、各奏者位置、勝利状態を持つ。移動のたびに開始状態から現フレーズを再計算できるため、undoが状態差分の破損を起こさない。

拍扉のある部屋では、各拍の全奏者の移動意図を先に算出する。壁と境界を解決後、対応する起動盤へ別奏者が同拍に到達する扉だけ移動を許可する。`ensemblePositions`が過去フレーズと現在フレーズを一括再計算するため、undo、reset、描画、勝利判定で扉状態が分岐しない。

反転床は`Room.inversionFloors`でデータ化する。`ensemblePositions`は現在録音中のphrase indexを受け取り、過去奏者だけに反転状態を持たせる。過去奏者が床へ入った次のstepからleft/rightを交換し、同じ床へ入り直すと状態を再反転する。現在奏者は常に入力どおりに動くため、録音時と再演時の差が決定的に再現される。

静寂帯は`Room.silenceFloors`でデータ化する。過去奏者が帯へ入ると奏者別のpending状態を立て、次のstepだけ入力を`wait`へ置換してpendingを解除する。置換された奏者は同じマスに残っても再度pendingにならないため、次の入力から譜面を続行できる。現在録音中の奏者にはpendingを立てない。

反転と静寂が同じ再演へ作用する場合は、まず反転状態から左右入力を変換し、その後に静寂pendingがあれば一拍だけ`wait`へ置換する。静寂は反転状態を解除しない。この順序を第8室の拍ごとの単体テストで固定する。

フレーズ長は`Room.phraseLength`を唯一の基準とし、入力上限、録音確定、HUDの拍数と拍マーカーを同じ値から生成する。第9室の6拍と第10室の10拍で、各終端入力の確定、過去2本の再演、最終拍の勝利、保存後の部屋先頭復帰を単体・Chrome E2Eで固定する。第11室では同じ6拍モデルへ既存の全奏者同時解決をそのまま組み合わせ、4拍目の起動と通過を決定的に解決する。第12室では反転、静寂、扉を同じ`ensemblePositions`内で順に解決し、変換された奏者が7拍目に作る起動状態で別奏者の扉移動を許可する。拍マーカー間隔は表示幅と拍数から算出し、10拍でもHUDパネル内へ収める。

## 決定性

同じ部屋、過去フレーズ、現在入力なら常に同じ位置と結果になる。ランダム性は縦切りに入れない。将来の演出乱数も規則乱数から分離する。

## 保存

`chorus-shift:v1`へschema version 1として、到達可能な最大部屋、完了部屋、ヒント閲覧用領域、音量、動きの軽減を保存する。途中フレーズ、現在拍、録音済みVOICEは保存せず、再訪時は選択した部屋の第1フレーズへ安全に戻す。

`persistence.ts`はJSON解析、範囲検証、重複除去、進行更新、設定更新を画面から分離する。破損JSON、未知version、部屋数外の値、localStorageの読み書き例外はゲームを止めず初期値へ戻す。初回の動きの軽減だけOSの`prefers-reduced-motion`を既定値に使い、以後は明示設定を優先する。

## 配信

`npm run build`で静的ファイルを生成する。v5公開経路は完成監査まで既存Pages workflowへ接続しない。

## ブラウザ検証

Playwrightからproduction previewを起動し、端末のGoogle Chromeを1 workerで操作する。規則を直接呼ばず、キーボードイベントとCanvasの`data-*`状態だけで12部屋の通し、6拍・10拍の録音確定、拍扉、変換床、終演、保存、設定、ヒント、ポーズ、viewportを検査する。`npm run verify`は単体、型検査、buildの後にE2Eまで一括実行する。

Canvasはフォーカス可能にし、画面・部屋・拍・録音声・奏者座標・音盤座標をDOMの動的説明へ同期する。入力ごとの位置はlive regionへ通知する。移動キーは全て離すまで次の移動入力を受けないため、OSリピートや方向キーの重複を一拍として扱う。4:3より縦長の画面では、縮小Canvasを補う14px以上のHTML状態パネルを表示する。
