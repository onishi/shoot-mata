# M4 アクセシビリティ監査

実施日: 2026-11-03

## 発見と修正

- Canvasがフォーカス不能で、読み上げ名も固定だった。`tabindex`、明瞭なフォーカスリング、操作説明、画面・部屋・拍・録音声・奏者座標・音盤座標の動的説明を追加した。各入力後は拍と全奏者位置をlive regionへ通知する。
- OSのキーリピートで一度の長押しが複数拍になり、二方向の同時押しも二拍として解釈され得た。移動キーを全て離すまで次の移動入力を受けないラッチを追加し、1押下1拍を固定した。ポーズやヒントなど移動以外の操作は保持中も利用できる。
- 640×800ではCanvas内の11〜15px文字が縮小され、実寸約5〜7pxになっていた。狭い縦長viewportでは、現在状態、目的、拍、奏者・音盤座標、画面固有操作を14〜16pxのHTMLパネルにも表示する。
- 初回ロード時とポインタ操作時にCanvasへフォーカスを戻し、キーボードだけでタイトルから操作できる状態を明示した。

## 自動検証

- 初期フォーカスと可視フォーカス対象
- タイトルおよび演奏中の動的accessible name / description
- 450ms長押しと方向キー重複中も1拍だけ進むこと
- 全キーを離した後の次入力は正常に1拍進むこと
- live regionが拍と位置を通知すること
- 640×800の状態パネルが表示され、本文14px以上でCanvasもviewport内に収まること
- 既存の全12室通し、設定・保存、主要6状態×2 viewport、高密度フレーム性能

`npm run verify`は単体43/43、型検査、production build、Google Chrome E2E 4/4に合格した。全12室282入力は5,456.9ms、高密度119フレームはp95 16.80ms、34ms超0%だった。

## 目視

`m4-viewport-playing-640x800.png`と`m4-viewport-settings-640x800.png`を確認した。Canvas、金色のフォーカスリング、14px以上の状態パネルが分離して表示され、欠けや重なりはない。設定画面では設定専用操作、演奏画面では演奏専用操作へ切り替わる。

## 残課題

- VoiceOver等の実スクリーンリーダーによる聴取順序と冗長さは、人間による支援技術実機評価が必要。
- 初見理解、効果音の聴感と音量バランス、release artifact監査は別のM4作業として残る。
