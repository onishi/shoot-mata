# Technical design

## 構成

- TypeScript + Canvas 2D + Web Audio
- Viteによる開発・production build
- 規則モデルはDOMと描画から分離し、60Hz固定刻みで決定的に更新する
- Vitestでスポーン、波紋、被弾、補充、勝敗、固定入力の到達性を検証する

## 状態

`title / playing / paused / won / lost`を明示し、ゲーム状態は面ID、プレイヤー、月花耐久、波紋残量、経過時間、胞子、波紋、スコアから成る。面定義は名前、目的文、制限時間、スポーン列を持ち、同じ決定的モデルで実行する。

通常胞子は波紋の円周との接触で押し返す。重い胞子は単独波紋を無視し、同一tickで2つ以上の波紋円内に含まれた場合だけ、2中心の中点から外向きに押し返す。反応済み波紋IDを胞子へ記録し、同じ組み合わせの多重反応を防ぐ。

移動面では月花位置を面IDと時刻から決定的に算出する。胞子は定義された到達時刻の月花位置を目標として出現し、被弾判定は現在の月花位置に対して行う。予測目標はモデルに保持して描画だけが参照する。面ごとの波紋最大半径により、MOONWAKEでは花への追従を位置判断として成立させる。

DEW CROSSINGも同じ決定的な月花軌道を使うが、4群に対して初期波紋を3回に制限する。岸判定と0.85秒の補充規則は共通のまま再利用し、移動対象、短い波紋、有限資源の組み合わせを専用分岐なしで成立させる。

ECHO TIDEは同じ月花軌道、速度種別、重い胞子、共鳴判定をデータ定義だけで組み合わせる。前半の高速群と後半の重い群へ初期3波紋を1+2で配分し、専用の物理分岐を追加しない。最終勝利後だけUIの`ending`画面へ遷移し、ゲームモデルの`won`状態は他面と共通に保つ。

## 性能予算

- 1280×720で60fpsを目標
- 同時胞子24、波紋6を上限とする
- 外部runtime requestを不要にする

## 製品設定

音量、高コントラスト、モーション軽減を`ripplekeep:v6:settings`へ保存する。読込時はJSONの構造、型、音量範囲を検証し、不正値は削除して既定値へ戻す。保存APIが利用不能でもゲームを止めない。

## ブラウザE2E

PlaywrightからGoogle Chromeを起動し、キーボード入力と60Hzループを仮想時計で進める。Canvasの`data-*`属性は画面、面、耐久、波紋残量、排除数、表示設定の読み取り専用観測点とし、ゲーム状態の直接書換えには使わない。1280×720と640×800でCanvasと設定カードの境界、16:9比率、狭幅の状態別操作案内を検査する。
