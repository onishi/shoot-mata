# v13.1 第一批評 — 初回理解・視認性・テンポ

## v13.0 baseline

- 規模: 決定的習熟14.67分、初見代理18.29分、状態注入なしChrome習熟14.19分。M4横断は14.69分、全18波×三陣・6守護者、BELL 1、6,364,275点。
- 入力傾向: M4横断で操作1,665回中投擲361回（21.7%）。決定的操縦は接近度と役割を評価して対象を選ぶが、外部初見プレイヤーの対象選択率ではない。
- 製品性: 破損保存復旧、動き軽減ON、投擲`Z`、60fps、勝利後`BBB`成績、console error 0。
- 画面: アトラクトからランキングまで12状態×640×480／1280×720の24画面に切れ、意図しない重なり、判別不能なし。
- 音: 48kHz実PCMで27効果音・6曲が非無音かつpeak 0.98未満、最悪重畳0.158099、停止状態は無音。
- 既知制約: 初見18.29分は入力制限代理で外部初見実測ではない。実筐体スピーカー聴感は未確認。公開・hash・旧版URL監査は未着手。

## 独立批評

1. タイトルと実演は往復を示すが、初回プレイへ入ると`CAST — MOVE — CATCH`が一度に出るだけで、今どの行動をすべきかを段階的に教えない。
2. 敵の距離は読めるが、鐘への到達直前に失敗原因を強調する共通記号がなく、多種混成では優先順位を観客が即断しにくい。
3. 回収失敗の0.8秒待ちは文章だけで、入力不能が故障なのかペナルティなのか、いつ終わるのかが見えない。
4. 波説明は完全な英文二行で、反応敵が増える後半ほど「何がきっかけで、何が動くか」の抽出に時間がかかる。
5. Chrome監査が固定ポートの既存サーバーを再利用し、別版を通しても合格し得る。実際に最初の再監査が残存v13.0を開いており、画面目視で発見した。

## 採用した改善

- 第1波だけ、`投擲→青い往路→金の復路へ移動→回収`を実状態に追従する短いコーチで表示する。失敗時は再投擲へ戻し、説明のために時間停止しない。
- 距離0.46未満の敵から鐘へ赤い破線を引き、`!`と線幅も併用して色だけに依存しない危険表示にする。
- 再投擲待ちをプレイヤー周囲の0.8秒円形ゲージと`RECAST`で表示する。
- 全17波説明へ短い規則帯を追加する。再配置キーを表示し、固定キー文言と矛盾する下段メッセージは重ねない。
- Chrome監査を実行ごとの一意ポートへ分離し、タイトルが`RINGWARD v13.1`でなければ開始直後に失敗させる。誤版の15.73分結果は証拠に採用しない。

## 改善後と非退行

- `npm run verify`: 単体53/53と全ソース構文に合格。コーチの投擲、復路、回収成功、失敗、再投擲を回帰固定した。
- `npm run audit:quality`: `auditedVersion: RINGWARD v13.1`、15.55分、全18波×三陣、6守護者、コンティニュー1回、BELL 3、8,637,450点、操作1,725回中投擲380回（22.0%）、60fps、console error 0、勝利`BBB`首位。
- 24画面を再採取した。`m4-quality-playing-1280x720.png`と640×480で初回コーチがHUDと敵を隠さず、`m4-quality-wave-brief-1280x720.png`で規則帯が二行説明と区別できることを比較目視した。
- 15.55分は習熟14〜20分契約内で、全区間、設定、保存、コンティニュー、結果導線は非退行。外部初見の理解改善は未実測なので、代理表示改善として限定して扱う。
