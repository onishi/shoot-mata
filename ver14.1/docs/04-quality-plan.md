# Quality plan

## M1

- `npm run verify`で操舵境界、サージ消費、救助範囲、破砕、被害、全イベントと終着を検証する。
- 一意ポート4314で `TIDEBREAK 95 v14.0` をassertし、状態注入なしにEnter、左右、Spaceを実入力する。
- 1280×720と640×360でタイトル、通常救助、街路、横流、バージ、結果を目視する。
- 連続フレームで入力前、サージ立上がり、救助／破砕結果を比較し、操作の手触りを批評する。

## 後続

M2で設定・保存破損・音量・ポーズ復帰・性能を追加する。M3で習熟方針の全5区間とボスの時間、救助率、被害、分岐選択を測る。M4で初見相当・救助優先・得点優先の複数方針、全ボス、音量peak、全主要画面を横断する。M5は独立批評を2回行い、クリーンbuildと公開hashを確認する。

M2の動作中表現は、通常航行、操舵、サージ、救助の連続画面とWeb Audioパラメータを同じ実Chrome通しで採取する。監査は`mode=cleared`へ到達しなければ失敗とし、バックグラウンド抑制による途中終了を合格扱いしない。

M2の製品監査は、操舵中のフォーカス喪失で作者時間・入力・連続音が停止し、前面化後のP入力で古い操舵なしに復帰することを確認する。復帰後60秒で2,500 frame以上、平均18ms以下、最大80ms以下を予算とし、結果をJSONへ残す。

M3の区間監査は、水路中心・半幅・流れを区間全体で約0.5秒ごとに採取し、名称や色を隠しても走路変形と操舵外力から前区間との差を説明できることを確認する。排他的救助は左右の同時表示、選択記録、未選択側の閉鎖を単体検証と状態注入なし通しの両方で追跡する。

地下放水路は約0.32秒ごとの深度、最大深度0.68以上、潜水後の0.32以下への再浮上、深層・表層双方の救助、無被害完走を状態注入なしの実キー通しで確認する。低天井と吸入口は安全閾値の単体検証を持ち、区間境界後に到達不能な障害が残らないことを船体値で検査する。

地下放水路の製品尺監査では、深度0.58以上でのみ2基の排水弁を操作でき、各組の片側だけが履歴へ残ること、選択が後続の水路形状・水位・障害・救助層を変えることを単体検証する。状態注入なし通しでは弁2/2、深層・表層双方の救助、船体3、後続2区間の非退行を確認し、OSフォーカス変動による安全停止を監査失敗と混同しないよう監査タブのfocus emulationを固定する。

倒壊コンテナ港の製品尺監査では、積載でフェリー追従が遅くなり、Spaceの隊形回復が通常追従より速いことを単体検証する。状態注入なし通しで積載救助2/2、潮位別航路2/2、条件付き障害を含む崩落11/11、潮位切替6回以上、船体・フェリー耐久3、後続高潮防壁12/12を確認する。積載、航路、低潮・高潮を動作中に別々に捕捉し、1280×720と640×360で艇、同行船、予告、HUDが重ならないことを目視する。

最終ボス監査では、状態注入なしの実キー通しでアンカー2/2、船腹3/3、上下排水2/2、コア撃破、船体3を必須にする。アンカー、船腹壁走行、内部排水、コアを動作中に別々に捕捉し、既存5区間の全条件も同じ通しで非退行を確認する。サージは0.56秒のため、監査の入力標識は接触約0.43秒前まで待ち、単体テストで実時間刻みの保護継続を固定する。

高潮防壁は約0.2秒ごとの高潮圧、艇・フェリー位置、壁走行側、門操作入力、クリア数、設備選択、安全区画収容を採取する。左右両方の壁走行を動作中に捕捉し、12門すべてで指定側と上下レバーを満たすこと、2設備が排他的に後続水路と門を変えること、積載済みフェリーを耐久3のまま安全区画へ収容することを単体検証と状態注入なし通しで確認する。

## M1非合格時

テスト合格を面白さの証拠にしない。操舵の予備動作と収束、サージ直後の速度・音・航跡、救助時の吸着感、4局面の画面構造を実プレイで比較し、撤退条件に該当すればM0へ戻す。
