# Decisions

## 2026-11-16 — 地下放水路を上下層の往復攻略にする

旧50〜75秒の横流と平面障害を廃止し、下入力で潜る低天井、上入力で浮く吸入口、深度により救助可否が変わる作業員へ置き換えた。潜水を回避専用にすると既存操舵の軸追加で終わるため、深層救助・表層救助・終端の上下分岐を同じ深度へ結び、救助幻想を維持した。最終イベントが75秒の区間境界後に到達して不可避被害になる初回監査結果を受け、境界を越える低天井を削除し、無被害で両層を通れる配置を採用した。

## 2026-11-16 — 浸水商業区を動くS字走路と排他的救助へ変更

背景色と障害配置だけだった25〜50秒を、水路中心・幅・交差流が連続変化する固有空間へ置き換えた。分岐は単なる左右の得点物にせず、同時に現れる二つのSOSから片方を救うと他方が閉じる。これにより外港の「対象へ寄って全回収」から、流向と次の曲がりを見て救助ルートを選ぶ攻略へ目的を変える。水路形状は描画専用にせず決定的モデルと艇の衝突境界へ同じ値を使う。

## 2026-11-15 — 設定をゲーム画面内の救難コンソールへ統合

HTMLの別フォームではなくタイトルの`S`からCanvas内設定を開き、音量、動き軽減、操舵・サージ再割当を同じ視覚言語で操作する。設定を独立モジュールへ分け、localStorageが壊れても既定値へ自己復旧させる。ゲーム中に突然開く誤操作を避けるため入口はタイトルだけとし、開始・ポーズ・再試行は製品キーとして固定した。実ブラウザでA/D/W再割当後のA入力到達と再読込保持を確認済み。

## D-001 前進型レスキューレーサーを採用

二機同時操作は10秒理解、列車リズム格闘は拍理解前の打撃品質に致命的リスクがあった。TIDEBREAKは左右とSpaceだけで主役、目的、移動、成功を一画面に出せ、失敗中も操舵が遊びになるため採用した。M1撤退条件はproduct briefに固定した。

## D-002 サージを攻撃ではなく多目的な救難航跡にする

無敵や破壊だけでは一般的なブーストになる。救助範囲拡大、軽瓦礫破砕、ゲージ消費を同じ0.56秒へ結び、いつ使うかを位置取り判断にした。コンクリートと大型船は破壊不能として回避を残す。

## D-003 M1を94秒の4局面にする

10秒の感触だけで採用を確定せず、同じ入力が開水面、狭窄、横流、大型施設で発展可能か早期に確認する。製品版の5区間をこの短い試作で代替しない。
